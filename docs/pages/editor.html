The Map Editor

Note: The editor provides direct visual layout while preserving advanced directives that remain easier to maintain in the configuration file. It is the quickest way to arrange a map and pick TARGETs when using Cacti.

New in version 0.7, there is a partially-complete interactive editor included. In this release, it allows for visual layout of nodes and links, modification of most parameters, and some integration with Cacti for picking data-sources. In the Cacti plugin, access is controlled through the Weathermap editor realm.

To use the editor, you need to make a few extra considerations beyond those needed by the command-line weathermap software, as detailed in the Installation Guide.

Once you have all that taken care of, put a copy of one of your configuration files into the configs directory you just created, and then go to: http://www.your.web.server/cacti/php-weathermap/editor.php (or whereever you put it). You should get a menu to either create a map, or open the ones you just put in that directory.

The editor supports direct manipulation as well as property dialogs.

Direct map movement

Drag a node, legend, or timestamp to a new position and release it to save immediately. During node movement, the editor also shows affected relative nodes and a preview of connected links. The rendered map is refreshed from the server after the configuration has been saved.

Nodes, legends, and timestamps are positioned directly by dragging them on the map. For keyboard operation, focus one of those elements and press Space to pick it up. Use the arrow keys to move it, hold Shift for larger steps, then press Space or Enter to save. Press Escape or Tab to cancel. The status control reports saving, saved, and conflict states. Undo is offered only when the editor can reverse the move without changing advanced link geometry.

  • You can click on any existing node or link to get its properties and change them.
  • You can delete a node or link from the properties box. Existing map elements are moved only by direct dragging or the keyboard drag controls.
  • If you set up the Cacti-related options in the editor-config.php file, then you should also see an additional option to pick a data source directly from Cacti, in the Link Properties box.
  • To create a new node, choose the 'Add Node' button at the top and then click on the map where you want the node to be.
  • To create a new link, choose the 'Add Link' button then click on the two nodes to link together, in turn. There are separate buttons at the top for changing various global parameters.
  • There is no page-level save button. Every confirmed change is written back to the configuration immediately. Direct-movement drops use revision checks and atomic replacement so one editor cannot silently overwrite a newer change. The configuration file and its directory must be writable, and the file must be owned by the web-server account so its owner, group, and mode can be preserved during replacement. File-specific ACLs and extended attributes are not copied to the replacement file; use standard ownership and mode bits for editable map configurations. Read-only maps and nodes defined by included files are visibly locked.

There are a number of things not editable in the editor currently:

  • Uploading background images and icons. Existing server-side images can be selected in the map and node property dialogs.
  • Colours. There is no visual colour or scale editor currently.
  • defaults - the editor lags behind the current command-line software here. It generates 'old-style' global options for some features where the correct thing to do is make changes to the DEFAULT link and node definitions. Similarly, there is no per-node or per-link adjustment of things like font, label style or label offset.
  • NODE TARGETs
  • Multiple SCALEs
  • Curves
  • Link offsets or Label offsets
  • Link VIA waypoint positions. Maintain advanced waypoint geometry in the configuration until direct waypoint drag handles are available.
Luckily, the editor shouldn't damage any of these things that you put into the configuration file by hand, so it's safe to do some work in the editor where it's quicker or more intuitive, and then fine-tune the file by hand.
